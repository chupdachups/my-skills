# 분석 보고서 형식 가이드

## 점수 기준 (0~100)

| 범위 | 등급 | 의미 |
|------|------|------|
| 90~100 | S | PLAN 완벽 충족, 코드 품질 우수 |
| 80~89  | A | PLAN 대부분 충족, 경미한 문제 |
| 70~79  | B | PLAN 주요 항목 충족, 일부 누락 |
| 60~69  | C | PLAN 절반 이상 충족, 수정 필요 |
| 0~59   | F | PLAN 요구사항 미충족 |

## 분석 에이전트 반환 JSON 스키마

```json
  ],
  "weaknesses": [

  "recommendation": "추천 - 소규모 수정 후 병합 가능"
}
```

## 최종 보고서 구성 순서

1. **헤더**: 분석 스킬, PLAN 파일, 개발 스킬
2. **브랜치별 상세**: 점수, 요약, 강점/약점, PLAN 충족도
3. **순위표**: 점수 내림차순 정렬
4. **추천**: 최고 점수 브랜치와 이유
5. **다음 행동**: git checkout / PR 생성 명령어

## 동점 처리

점수가 같을 경우 다음 순서로 우선순위를 결정하세요:
1. PLAN 충족도가 높은 브랜치
2. 약점이 적은 브랜치
3. 변경 파일 수가 적은 브랜치 (최소 변경 원칙)
