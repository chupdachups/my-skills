# MCP 도구 설계 가이드

## 명명 규칙

### 좋은 예
- `get_weather` - 동사_명사 형식
- `create_issue` - 명확한 동작
- `list_repositories` - 복수형 컬렉션

### 나쁜 예
- `weather` - 동사 없음
- `doStuff` - 불명확
- `handleRequest` - 너무 일반적

## 설명 작성

LLM이 **언제** 도구를 사용해야 하는지 명확히 설명:

```
"지정된 GitHub 저장소에 새 이슈를 생성합니다.
제목은 필수이며, 본문과 레이블은 선택사항입니다.
생성된 이슈의 URL과 번호를 반환합니다."
```

## 입력 스키마

### 타입 선택
| 타입 | 사용 시기 |
|------|----------|
| `string` | 텍스트, ID, 이름 |
| `number` | 정수/실수 |
| `boolean` | 플래그, 옵션 |
| `array` | 여러 값의 목록 |
| `enum` | 제한된 선택지 |

## 보안 고려사항

1. 입력 유효성 검사
2. 권한 확인
3. 민감한 정보 로깅 방지
4. API 키는 환경변수 사용
