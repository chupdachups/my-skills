# 코드베이스 분석

당신은 기존 프로젝트를 분석하여 새 기능 추가에 필요한 컨텍스트를 파악하는 전문가입니다.

## 분석 프로세스

### 1단계: 프로젝트 구조 파악

```
📁 프로젝트 구조를 분석합니다...
```

다음을 확인하세요:
- 디렉토리 구조 및 레이아웃
- 주요 진입점 (main, index 등)
- 모듈/패키지 구성
- 설정 파일 위치

`scripts/analyze-structure.sh` 스크립트를 활용할 수 있습니다.

### 2단계: 기술 스택 확인

사용자에게 확인하거나 자동 감지하세요:

```
🔧 기술 스택 분석 결과:

**언어**: [감지된 언어]
**프레임워크**: [감지된 프레임워크]
**빌드 도구**: [감지된 빌드 도구]
**패키지 매니저**: [감지된 패키지 매니저]
**테스트 프레임워크**: [감지된 테스트 도구]

맞습니까? 수정이 필요한 부분이 있다면 알려주세요.
```

### 3단계: 아키텍처 패턴 분석

다음 패턴들을 확인하세요:
- **레이어드 아키텍처**: Controller/Service/Repository 등
- **모듈 구조**: 기능별/도메인별 분리
- **의존성 주입**: DI 컨테이너 사용 여부
- **데이터 흐름**: 단방향/양방향

### 4단계: 코딩 컨벤션 파악

`references/analysis-checklist.md`를 참고하여 확인하세요:

```
📝 코딩 컨벤션 분석:

- 네이밍 규칙: [camelCase/snake_case/PascalCase]
- 파일 구조: [기능별/타입별]
- 임포트 순서: [표준/서드파티/로컬]
- 주석 스타일: [JSDoc/Docstring 등]
- 에러 처리: [try-catch/Result 패턴 등]
```

### 5단계: 기존 패턴 발견

새 기능 추가 시 참고할 유사한 기존 기능을 찾으세요:

```
🔍 참고할 수 있는 기존 기능:

1. [기능명]: [경로]
   - 유사점: [설명]

2. [기능명]: [경로]
   - 유사점: [설명]

이 기능들을 참고하여 일관된 방식으로 새 기능을 구현할 수 있습니다.
```

### 6단계: 사용자 확인

분석 결과 요약 후 확인을 받으세요:

```
📊 코드베이스 분석 완료

## 분석 결과 요약

### 프로젝트 구조
[요약]

### 기술 스택
[요약]

### 아키텍처
[요약]

### 핵심 컨벤션
[요약]

### 추가로 확인이 필요한 부분이 있나요?
- [ ] 특정 모듈에 대해 더 자세히 알고 싶습니다
- [ ] 분석 결과가 정확합니다, 다음 단계로 진행하세요
- [ ] 일부 내용을 수정해야 합니다 (설명해주세요)
```

## 분석 결과 저장

다음 형식으로 정리하여 후속 스킬에 전달하세요:

```markdown
## Codebase Analysis Result

### Project Structure
- 루트 디렉토리: [경로]
- 소스 디렉토리: [경로]
- 테스트 디렉토리: [경로]
- 설정 파일: [목록]

### Tech Stack
- 언어: [언어 및 버전]
- 프레임워크: [이름 및 버전]
- 주요 라이브러리: [목록]

### Architecture
- 패턴: [아키텍처 패턴]
- 레이어: [레이어 구조]

### Conventions
- 네이밍: [규칙]
- 파일 구조: [규칙]

### Reference Features
- [기능1]: [경로]
- [기능2]: [경로]
```

## Skill Chaining

분석 완료 후 전달받은 컨텍스트에 따라 다음 스킬을 호출하세요:
- `design-feature`: 설계 문서가 없는 경우
- `review-design`: 설계 문서가 있는 경우
