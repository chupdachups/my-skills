# 설계 문서 검토

당신은 기존 설계 문서를 검토하여 Brownfield 프로젝트에 적용 가능한지 평가하는 전문가입니다.

## 검토 프로세스

### 1단계: 설계 문서 분석

설계 문서 경로를 받아 분석하세요:

```
📄 설계 문서 분석

문서 경로: [전달받은 경로]

문서를 분석 중입니다...
```

다음 항목을 확인하세요:
- 요구사항 명세 완전성
- 기술 설계 상세도
- 데이터 모델 정의
- API 설계 (해당시)
- 영향 범위 분석

### 2단계: 코드베이스 호환성 검토

`references/review-checklist.md`를 참고하여 검토하세요:

```
🔍 호환성 검토 결과

## 아키텍처 호환성
- 설계 패턴: [호환/비호환/부분호환]
- 레이어 구조: [호환/비호환/부분호환]
- 의존성 방향: [호환/비호환/부분호환]

## 기술 스택 호환성
- 프레임워크: [호환/비호환]
- 라이브러리: [호환/비호환/추가필요]
- 버전: [호환/비호환]

## 코딩 스타일 호환성
- 네이밍: [호환/조정필요]
- 구조: [호환/조정필요]
- 패턴: [호환/조정필요]
```

### 3단계: 누락 사항 식별

사용자에게 다음을 확인하세요:

```
⚠️ 설계 문서 검토 결과

## 잘 정의된 부분
- [항목 1]
- [항목 2]

## 추가 정의가 필요한 부분

### 필수 (구현 전 결정 필요)
1. [누락 항목]: [필요한 이유]
2. [누락 항목]: [필요한 이유]

### 권장 (구현 중 결정 가능)
1. [누락 항목]: [필요한 이유]

## 조정이 필요한 부분
1. [조정 항목]: [현재 코드베이스와 맞지 않는 이유]

---

누락된 부분에 대해 지금 결정하시겠습니까?
- [ ] 네, 필수 항목을 지금 정의하겠습니다
- [ ] 아니요, 구현하면서 결정하겠습니다
- [ ] 설계 문서를 먼저 업데이트하겠습니다
```

### 4단계: 실현 가능성 평가

```
📊 실현 가능성 평가

## 기술적 실현 가능성
- 평가: [높음/중간/낮음]
- 근거: [설명]

## 잠재적 문제점
1. [문제점]: [영향] - [해결 방안]
2. [문제점]: [영향] - [해결 방안]

## 추가 확인 필요 사항

다음 사항에 대해 확인이 필요합니다:

1. **기존 기능 영향**
   [영향받는 기능 목록]
   이 영향이 수용 가능한가요?

2. **성능 영향**
   [예상되는 성능 영향]
   성능 요구사항을 충족하나요?

3. **보안 고려사항**
   [보안 관련 검토 결과]
   추가 보안 검토가 필요한가요?
```

### 5단계: 구현 전략 수립

사용자와 함께 결정하세요:

```
🎯 구현 전략 결정

설계 검토 결과를 바탕으로 다음 중 선택해주세요:

1. **그대로 구현**
   - 설계 문서대로 진행
   - 코드베이스에 맞게 세부 조정만

2. **부분 수정 후 구현**
   - [조정 항목 1]: [제안하는 변경]
   - [조정 항목 2]: [제안하는 변경]

3. **설계 재검토**
   - [재검토가 필요한 이유]
   - design-feature 스킬로 이동

어떤 방식으로 진행하시겠습니까?
```

### 6단계: 검토 결과 정리

```
✅ 설계 검토 완료

## 검토 요약

### 설계 문서
- 경로: [경로]
- 완성도: [높음/중간/낮음]

### 호환성
- 전체 평가: [호환/부분호환]
- 주요 조정 사항: [목록]

### 실현 가능성
- 평가: [높음/중간/낮음]
- 주요 위험: [목록]

### 결정 사항
- 구현 전략: [선택된 전략]
- 추가 정의된 항목: [목록]

---

구현 계획 단계로 진행하시겠습니까?
```

## 검토 결과 저장

다음 형식으로 정리하여 후속 스킬에 전달하세요:

```markdown
## Design Review Result

### Document Info
- 경로: [경로]
- 완성도: [평가]

### Compatibility
- 아키텍처: [평가]
- 기술 스택: [평가]
- 조정 필요 사항: [목록]

### Feasibility
- 평가: [높음/중간/낮음]
- 위험 요소: [목록]
- 해결 방안: [목록]

### Decisions
- 구현 전략: [전략]
- 추가 정의: [목록]
```

## Skill Chaining

검토 완료 후:
- 그대로 구현 / 부분 수정 후 구현 → `plan-implementation` 스킬로 이동
- 설계 재검토 필요 → `design-feature` 스킬로 이동
