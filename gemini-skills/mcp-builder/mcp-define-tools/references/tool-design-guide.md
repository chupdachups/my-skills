# MCP 도구 설계 가이드

## 도구란?

MCP 도구(Tools)는 LLM이 호출할 수 있는 동적 작업입니다. POST 엔드포인트와 유사하게 상태를 변경하거나 외부 시스템과 상호작용할 수 있습니다.

## 명명 규칙

### 좋은 예
- `get_weather` - 동사_명사 형식
- `create_issue` - 명확한 동작 표현
- `list_repositories` - 복수형으로 컬렉션 표현
- `send_notification` - 동작 결과 명확

### 나쁜 예
- `weather` - 동사 없음
- `doStuff` - 불명확
- `process` - 너무 일반적
- `handleRequest` - 구체적이지 않음

## 설명 작성

### 원칙
1. LLM이 **언제** 이 도구를 사용해야 하는지 명확히
2. **무엇을** 하는지 구체적으로
3. **제한사항**이나 **주의사항** 포함

### 좋은 예
```
"지정된 GitHub 저장소에 새 이슈를 생성합니다.
제목은 필수이며, 본문과 레이블은 선택사항입니다.
생성된 이슈의 URL과 번호를 반환합니다."
```

### 나쁜 예
```
"이슈를 만듭니다"
```

## 입력 스키마 설계

### 필수 vs 선택 파라미터
- **필수**: 도구 실행에 반드시 필요한 정보
- **선택**: 기본값이 있거나 없어도 동작 가능

### 타입 선택
| 타입 | 사용 시기 |
|------|----------|
| `string` | 텍스트, ID, 이름 |
| `number` | 정수/실수 숫자 |
| `boolean` | 플래그, 옵션 |
| `array` | 여러 값의 목록 |
| `object` | 중첩된 구조 |
| `enum` | 제한된 선택지 |

### 파라미터 설명
각 파라미터에 명확한 설명 제공:
- 예상 형식 (예: "YYYY-MM-DD 형식의 날짜")
- 유효 범위 (예: "1-100 사이의 정수")
- 기본값 정보

## 보안 고려사항

### 반드시 고려할 것
1. **입력 유효성 검사**: 모든 입력을 검증
2. **권한 확인**: 민감한 작업 전 확인
3. **속도 제한**: 과도한 호출 방지
4. **로깅**: 민감 정보 제외하고 기록

### 위험한 작업
- 파일 삭제/수정
- 데이터베이스 변경
- 외부 API 호출 (비용 발생 가능)
- 시스템 명령 실행

## 에러 처리

### 에러 응답 형식
```json
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "도시 이름은 필수입니다",
    "details": {
      "field": "city",
      "reason": "missing_required"
    }
  }
}
```

### 일반적인 에러 코드
- `INVALID_INPUT` - 입력 유효성 실패
- `NOT_FOUND` - 리소스 없음
- `UNAUTHORIZED` - 권한 없음
- `RATE_LIMITED` - 요청 제한 초과
- `EXTERNAL_ERROR` - 외부 서비스 오류
